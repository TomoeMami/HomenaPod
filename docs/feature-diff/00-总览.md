# AntennaPod ↔ HomenaPod 功能差异总览

> 基线：上游浅克隆 `antenna-repo/`（`d05a58b`，develop，2026-09-09，"Fix 3 tiny usability problems"），
> 检出范围 `app/src/main` + `ui/` + `storage/preferences`（`model`/`parser`/`net`/`playback`/`storage:database` 模块**未检出**，
> 涉及这些模块的结论以 UI 调用点与偏好键为据，并已在分域报告中标注）。
> 移植版：`antennapod-harmony/entry/src/main/ets`（97 个 `.ets`）。
> 取证方式：全量文件清单 + 逐域 read/grep，结论均带 `file:line`（见 4 份分域报告）。
>
> 状态图例：`✅ 对齐` · `🔸 简化/替代` · `⬜ 缺失` · `➕ 移植版独有` · `⛔ 平台不适用`

## 一、一句话结论

移植版把上游的**"订阅 → 解析 → 播放 → 队列 → 下载"主链路做全了**，
并且在**每 Feed 设置、队列排序、睡眠定时、自动下载**等"深度功能"上接近 1:1；
落差分两类：**① 功能缺口**——全局视图（Episodes 总表）、多选、生态集成（同步/投屏/小部件/车机/手表/深链/代理）、
内容增强（转录/视频/章节图/Echo）；**② 接线缺陷**——后台长时任务未启动、定时刷新不恢复、订阅页过滤/排序菜单死路等
（见下方"功能性缺陷"表）。

## 二、口径说明（为什么有"缺失"但不算 bug）

1. **平台能力边界**：上游依赖的 Android 独有设施在 HarmonyOS 无等价物，移植版做了显式降级并留档
   （跳静音、系统分享面板、SAF 数据目录、硬件键盘快捷键），见 `docs/harmony-counterparts.md`。
2. **产品改名**：AntennaPod → HomenaPod，`com.homenapod.app`，UI 文案/UA/会话名/DB 名全替换；
   这是有意的品牌隔离，不算功能缺失。
3. **UI 实现路径不同**：移植版按上游**相对布局**对齐（结构/顺序/层级），控件用鸿蒙原生；
   尺寸仅在冲突时偏离，见 `docs/07-ui-layout-parity.md`。

## 三、差异分类总表（高层）

## 五、后续建议（按性价比）

1. **Episodes 全局总表**：复用 `EpisodeRepository` 现有查询 + `EpisodeRow`，成本低、补上最大入口缺口。
2. **单集多选**：队列页已有完整多选实现（`QueuePage.selectedIds`），抽成公共选择态即可。
3. **转录展示**：数据层已就位（`podcastindex_transcript_*` 字段 + 解析），只差一个 Sheet + 富文本渲染。
4. **数据库导出/导入**：`DbManager` 已有 DDL，导出为 JSON/SQL 成本可控。
5. **同步（gpodder/Nextcloud）**：工作量大、需要账号生态，建议明确不做或后置。
6. **Echo / 视频 / 代理 / 家长控制**：收益有限，维持 backlog。
